Strategos, nine looks

The same eight sessions in each. Click a session to open it, press n to jump to the next one that needs you, t to flip between terminal and chat. Approve and reply work, so you can feel how fast each look is to act on.

The first four, compared

A · Dashboard

Reads fastest

Every session is a line with status, current tool, context and cost in fixed columns. Your eye finds the red ones without hunting.

Good for

  • 10 to 30 sessions at once
  • Keyboard use and inline approve
  • Cheapest to build and maintain

Gives up

  • The strategy-game feel. It looks like mission control, not a campaign.
B · Map

Most distinctive

Each repo is a planet and each session orbits it. Colour and glyph carry status, a ring around the token carries context fill.

Good for

  • Seeing which repo is busy
  • Feeling like a different product
  • Short lists, about 4 to 12 sessions

Gives up

  • Position means nothing, so you read labels anyway
  • Gets crowded past about 12 sessions
  • No room for last-message text
C · Hybrid · my pick

Map as navigator

The planets act as the repo picker and give a one-glance count. The rows underneath carry everything you need to act.

Good for

  • Glance first, detail one click away
  • Keeps a bit of the game look
  • The map can be improved later without touching the rows

Gives up

  • Slightly more to build than A alone
  • Less dramatic than a full map
D · HUD

The grand overview

The whole fleet on one radial display. Each repo owns a quadrant, and a session sits further out the fuller its context is, so trouble drifts toward the red rim.

Good for

  • Position that means something: angle is repo, distance is context
  • Spotting context pressure before it bites
  • A screen you leave on a second monitor

Gives up

  • Less text per session than rows
  • Labels crowd past about 16 sessions
  • More effort to build and keep smooth

What I would build first

Start with A, but build the repo chips from C into it from day one. That gives you the fast list now and a path to the full map later, because the map and the HUD only need the same session data the rows already use. If you want the HUD as the hero, I would keep the rows one keypress away for reading what a session actually said. Your goal is seeing everything at a glance in a window that replaces Claude, so scan speed matters more than the scenery.
