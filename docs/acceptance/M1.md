## Automated end to end (fake-claude, real daemon, real WebSocket client, real node-pty)

- start 3 sessions; one walked permission, `perm.decide allow` (via `drawer`, connection id in `audit.jsonl`), done;
- stop then resume (same Claude id, `--resume`), park then resume, double resume refused, forget;
- a `state.json` left by a dead daemon: sessions load as `stopped` (source `daemon`), resumable; a foreign live process owning the conversation blocks resume; `resumeAll` brings them back; `daemon.lock` live holder refused, stale replaced;
- `reply.send` refused while input is typed in the terminal (`dirty_input`) and while busy; accepted after Ctrl+C clears the prompt;
- `pending.full`, `pty.focus` auto-release (D13) then answered in the terminal, `pty.subscribe` replay before the ack and then streaming, `digest.get`;
- version guard: out-of-range version gives `hello.inRange=false` and `prefs.claudeVersionOutOfRange`; missing Claude gives a clear `session.start` error; the daemon keeps running;
- `/control/*`: no secret 401, wrong Host 421, any Origin 403, GET 405.

## Demo (real Claude, sandbox only)

```
npm run strategos -- start            -> Strategos started (pid 44300, port 51033).
npm run strategos -- status           -> strategos 0.0.0  pid 44300  port 51033  up 2s  claude 2.1.292 (Claude Code) / (no sessions)
npm run strategos -- status --watch   (second window)
node tools/demo-client.ts C:\dev\strategos-sandbox "Reply with the single word ok."
```

Client output (session started through a paired WebSocket, no permission prompt was raised):

```
+0.0s hello claude 2.1.292 (Claude Code) inRange=true
+0.2s session demo-ok: starting (user)
+3.1s session demo-ok: working (hook)
+6.3s session demo-ok: done (hook) last="ok"
+6.3s done -> stopping
+8.6s session demo-ok: stopped (hook) last="ok"
```

`status --watch` showed the same rows: `demo-ok starting (user)` -> `working (hook)` -> `done (hook)  ok` -> `stopped`. Then `strategos open --print` gave a one-time pairing link, `strategos stop` ended the daemon ("Strategos stopped. Sessions are saved and can be resumed."), and `status` afterwards read the saved state read-only.

Safety: only `C:\dev\strategos-sandbox`; `--permission-mode default`; no `--dangerously-skip-permissions`; no process left running; `daemon.lock`, `daemon.json`, `cli.secret` removed on stop.

`~/.claude/settings.json` sha256 before and after: `395251894b195ee1979471360b82fe92c86905430bfd3e5b5e8bab04780c360d` (identical; `settings.local.json` absent both times). Taken with `spike/hash-claude-dir.ts`.

## Not done / caveats

- `strategos open` launching Chrome with `--app` was not exercised here (only `--print`), to avoid opening a window on the owner's desktop.
- The status-line tap end-to-end under real Claude was not inspected in this demo (the session ended after one turn).
- Worktrees (`session.start` with `worktree`) are refused until M6.
